# Notebooks

| Notebook | What it does |
|---|---|
| [runpod_dataset.ipynb](runpod_dataset.ipynb) | One A100 pod with the network volume at `/workspace`: Hugging Face login and the JAX GPU environment, a smoke test and the full training of the expert (detached), the checkpoints to the Hub, the choice of early snapshots, the data collection (detached), the replay check, the dataset numbers (job D0), and the data and numbers to the same Hub repo |
| [relabel_dataset.ipynb](relabel_dataset.ipynb) | Once, on any machine with about 20 GB of disk: downloads the three files from the Hub, relabels the actions taken while asleep as noop (`action_policy` keeps the policy's choice), checks that every file replays and follows the rule, recomputes the dataset numbers, and replaces the files on the Hub (the old ones stay in its history) |
| [runpod_B1.ipynb](runpod_B1.ipynb) | B1, the flat baseline (level 1; it was F1 before 2026-11-02), and its planning, on one A100 pod: the PyTorch environment and the dataset from the Hub, a smoke run of the training on the real files (with the probes), the timing of a step, of the real data loader and of a planning solve (optionally the training file without compression), B1 (`run.py run B1`, 10 epochs, about 3.3 hours on an A100: training, loss curves, the probe suite, then the cheap P1 on task set A with the random baseline, the reference of the variants; detached, resumable; the suite again on B1 when its report is from an older suite), P2 and P3 (only for the final comparison with the hierarchy), and the runs and reports to the Hub. B1 keeps its folder `flat` (`pod.folder_of`) |
| [local_A3_A4.ipynb](local_A3_A4.ipynb) | A laptop, no pod: A3 and A4, the MLP-JEPA on the simulator state (`H-JEPA/h_jepa/state_jepa`, README "Ids"). The episode files linked into `data/local/` (its `HJEPA_HOME`, gitignored), a smoke run, `run.py run A3` and `run A4` (one epoch each, about 10 minutes on an M1 Max: 29 ms per step, a check of the latent 3 s), the report of both runs (`A4_trace.md` and its figure), and the reports and traces copied to `reports/A3_A4/`. `PYTHON` must have the H-JEPA requirements (CPU torch) |
| [runpod_bc_entities.ipynb](runpod_bc_entities.ipynb) | One analysis on one A100 pod, nothing is trained for the flat model: `H-JEPA/h_jepa/bc.py` trains a chunked behaviour-cloning MLP on the simulator `state` (the final expert's episodes, chunk lengths 4, 8 and 16) and measures which entities of the state its actions need (permutation importance as the share of its skill lost, with an episode bootstrap, by block and mob type, distance from the player, tile, item, vital, facing, daylight, sleeping; the model trained again without the coarse groups and the top entities), and the same for temporal distance (the states of frame t and of a later frame in, the gap out; daylight left out, it is a clock) and for multi-step inverse dynamics over 4 and 8 steps (the states of frame t and t+k in, the k actions between them out). Smoke run, the detached run, the reports and a figure, the reports to the Hub |
| `runpod_<ID>.ipynb` ([V1 rollout](runpod_V1.ipynb), [V2 SIGReg 0.03](runpod_V2.ipynb), [A1 balanced ablation](runpod_A1.ipynb), [A2 map decoder ablation](runpod_A2.ipynb)) | One notebook and one pod per variant or ablation (named by its id, README "Ids"), so they train in parallel: B1 and its P1 results from the Hub (planned or probed here only when missing), a smoke run of the run, then `run.py run <ID>` detached (training, the probe suite at its end, the cheap P1 on set A, the comparison with B1 and the random baseline in `reports/<ID>_*.md`), and the upload. The notebooks are the same apart from the title and the configuration cell (a test checks it): a new variant is a copy with its own `EXPERIMENT`, and a test asks for one notebook per `V` (variant) or `A` (ablation) experiment trained on a pod. A1 keeps its folder `flat_balanced`. Run `runpod_B1.ipynb` (its probe suite, its P1) and its upload first |

The helpers of the baseline and the variant notebooks are in [pod.py](pod.py) (paths, shell, detached jobs, the environment, the dataset, runs from and to the Hub). These notebooks keep the repository clone (`/root/AAC`, cloned by hand once per pod), its venv (`/root/venvs/hjepa`) and the episode files (`/root/data`, downloaded from the Hub) on the pod's local disk, because the network volume refuses `chmod` and stalls on the training file; checkpoints, reports and task files stay on the volume (`/workspace/data`, linked into `/root/data`); the logs (`/root/logs`) and stable-pretraining's folder (`spt_dir`, `/root/spt`) are written at every logging step and stay local, because the volume stalled the training about 10 s at each one. Weights & Biases is on (`USE_WANDB` in the configuration cell): the notebook asks for the API key, checks it in the pod cell and passes it to the training; without a key a training stops at its start (`No API key configured`). The notebook is stored without outputs. Edit the configuration cell (repo id, run length, frame counts, shares; for the baseline the epochs from the timing; the pod paths are in `pod.py`) and run the cells from the top; every long step runs detached and a step that finished is skipped when its cell is run again. Notes on the pod: [environment/README.md](../environment/README.md).
