# Notebooks

| Notebook | What it does |
|---|---|
| [runpod_dataset.ipynb](runpod_dataset.ipynb) | One A100 pod with the network volume at `/workspace`: Hugging Face login and the JAX GPU environment, a smoke test and the full training of the expert (detached), the checkpoints to the Hub, the choice of early snapshots, the data collection (detached), the replay check, the dataset numbers (job D0), and the data and numbers to the same Hub repo |
| [relabel_dataset.ipynb](relabel_dataset.ipynb) | Once, on any machine with about 20 GB of disk: downloads the three files from the Hub, relabels the actions taken while asleep as noop (`action_policy` keeps the policy's choice), checks that every file replays and follows the rule, recomputes the dataset numbers, and replaces the files on the Hub (the old ones stay in its history) |
| [runpod_flat.ipynb](runpod_flat.ipynb) | The flat model (level 1), the complete cycle, on one A100 pod: the PyTorch environment and the dataset from the Hub, a smoke run of the training on the real files (with the probes), the timing of a step, of the real data loader and of a planning solve (optionally the training file without compression), F1 (10 epochs, about 3.3 hours on an A100: training, an early probe of the epoch-1 checkpoint, loss curves, probes; detached, resumable), P1-P3 (F3-F5) after the planning settings are frozen, the variant V1, and the runs and reports to the Hub |

The flat notebook keeps the repository clone (`/root/AAC`, cloned by hand once per pod), its venv (`/root/venvs/hjepa`) and the episode files (`/root/data`, downloaded from the Hub) on the pod's local disk, because the network volume refuses `chmod` and stalls on the training file; checkpoints, reports and task files stay on the volume (`/workspace/data`, linked into `/root/data`); the logs (`/root/logs`) and stable-pretraining's folder (`spt_dir`, `/root/spt`) are written at every logging step and stay local, because the volume stalled the training about 10 s at each one. Weights & Biases is on (`USE_WANDB` in the configuration cell): the notebook asks for the API key, checks it in the pod cell and passes it to the training; without a key a training stops at its start (`No API key configured`). The notebook is stored without outputs. Edit the configuration cell (paths, repo id, run length, frame counts, shares; for the flat model the epochs from the timing) and run the cells from the top; every long step runs detached and a step that finished is skipped when its cell is run again. Notes on the pod: [environment/README.md](../environment/README.md).
